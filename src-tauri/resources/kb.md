# agent-principles
## 【必学】Agent 是什么
Agent（智能体）是以大语言模型（LLM）为核心，能够自主感知环境、做出决策并执行动作的软件系统。与传统程序"输入-规则-输出"不同，Agent 具备目标导向：你告诉它"完成什么"，它自己拆解"怎么做"。核心特征有三点：一是使用 LLM 作为推理引擎，二是能调用外部工具（工具即能力边界），三是有一个执行循环（不断观察结果、调整策略）。最简单的 Agent 闭环是"提问 → 模型推理 → 调用工具 → 观察结果 → 继续推理"。工作中你会遇到的典型 Agent：代码助手（自动改代码跑测试）、客服机器人（查订单改备注）、自动化运维（看日志定位问题）。面试常问"Agent 与普通 Chatbot 的区别"，答案要点：Chatbot 是"一问一答"，Agent 有目标、有工具、有循环。
## 【必学】LLM 驱动的 Agent 架构
一个生产可用的 Agent 通常由四部分组成：模型（大脑，负责理解与决策）、工具（手脚，如搜索、执行命令、读写文件）、记忆（上下文窗口、会话历史、外部知识库）、编排层（决定每一步调用谁）。工作流是：系统提示词定义角色与边界 → 用户目标输入 → 模型规划并生成工具调用请求 → 执行工具并返回结果 → 模型综合结果继续或结束。注意两个工程要点：一是模型输出要结构化（JSON 或专门工具调用协议），方便解析执行；二是每一步都要做错误处理，工具可能失败、模型可能输出非法调用。架构设计时优先考虑"最小闭环"：先让一个简单任务端到端跑通，再逐步加工具和记忆。
## 【必学】ReAct 模式：思考-行动-观察
ReAct（Reasoning + Acting）是 Agent 最经典的推理模式，核心是让模型交替输出三种动作：Thought（思考，解释为什么这么做）、Action（行动，选择工具并给参数）、Observation（观察，工具返回结果）。如此循环，直到得到最终答案。它的价值：把推理过程显式化，模型在每一步看到"事实-推理-证据"，比直接给答案准确率高得多，且过程可审计。实现时通常通过提示词约束输出格式（如规定每行以 Thought:/Action:/Observation: 开头），或使用模型原生的工具调用协议（function calling）让动作结构化。现在的先进 Agent（Claude Code、OpenAI Operator 等）底层都是 ReAct 的变体。练习：用提示词让 Claude 按 ReAct 格式回答一个多步问题，观察循环次数与答案质量。
## 【必学】Function Calling / 工具调用
Function Calling（函数调用）是模型输出结构化工具请求的机制：你预先声明一组工具（名称、参数 JSON Schema、描述），模型在推理时决定调用哪个并填好参数，应用执行后把结果回填给模型。这是 Agent 的"手脚"接口。关键点：一是工具描述要写清楚"什么时候用、参数含义"，模型靠描述选工具；二是参数校验要严（模型可能填错类型），应用层兜底；三是超时与幂等设计——网络工具可能失败，重试策略要提前想好。Claude 的 function calling 用 XML 标签（tool_use/tool_result），OpenAI 用 JSON 对象，原理一致。面试考点："模型幻觉参数怎么办"——答案：服务端校验 + 拒绝后让模型修正。
## 【必学】记忆：短期与长期
Agent 记忆分三层：上下文窗口（当次对话的全部输入输出，容量有限）、会话历史（多轮对话累积，通常截断或摘要保留最近 N 轮）、长期记忆（跨会话保存：用户偏好、项目知识、外部知识库）。工程上：短期记忆用"滑动窗口 + 关键信息摘要"；长期记忆主流做法是 RAG（向量化存储 + 语义检索）和结构化记录（数据库存用户画像/事实）。记忆越界的处理：上下文放不下时，把旧消息摘要成一段文字替代。设计原则：重要事实优先保留（用户 ID、目标、决策记录），闲聊可丢弃。Claude Code 的 CLAUDE.md 与 Memory 就是长期记忆的实例——把重要约定写下来，下次会话自动加载。
## 【选修】规划、反思与自我纠错
复杂任务单轮推理不够，需要显式规划：Plan-and-Execute 模式把任务拆成步骤列表逐步执行，比让模型一步到位更可控。进阶技术：反思（Reflection），让模型对自身输出打分、找错、重写——一个经典做法是"先生成答案，再让另一个视角的提示词挑错，再根据错误重写"，准确率明显提升。还有自我纠错循环：执行失败 → 读错误信息 → 调整计划重试（Claude Code 遇到编译错误会自己修就是例子）。工程注意：反思要限制轮数（如最多 2 次），防止死循环烧 token；记录每次失败的教训到记忆，避免重犯。这是 Agent 工程师的进阶分水岭：能把"能跑"做到"可靠"。
## 【选修】多 Agent 协作
多 Agent 协作是多个 Agent 分工配合解决复杂问题：主 Agent 拆解任务并分发给子 Agent，各子 Agent 返回结果由主 Agent 汇总。常见模式：编排者-工作者（orchestrator-worker，一个主控多个执行）、流水线（前一个输出是后一个输入）、辩论（多个 Agent 对同一问题给观点互相质疑）。收益：每个 Agent 专注一个领域，上下文更干净；风险：成本成倍增长、协调复杂度高、错误会传播放大。实践建议：能用单 Agent 解决就不要上多 Agent；多 Agent 之间要定义清晰的"接口"（输入输出格式、验收标准）。Claude 的 Subagents 功能就是这种模式的工程实现——每个子代理有自己的指令与工具集。
# toolchain
## 【必学】提示词工程基础
提示词是给模型的行为说明书，工程上五个要素：角色（你是谁）、任务（要做什么）、输入（数据长什么样）、约束（格式、字数、不许做什么）、示例（Few-shot，给 1-3 个输入输出样例比纯描述效果好）。进阶技巧：链式思考（让模型先推理再给答案）、输出结构化（明确要求 JSON 或 XML 并给 Schema）、否定式约束要写明替代行为（"不要编造"不如"不确定就回答不知道"）。评判提示词好坏的标准：同样的输入，提示词 A 和 B 哪个结果稳定。注意：提示词不是唯一杠杆，调不动时先看数据与工具。面试题："提示词注入怎么防"——系统层隔离（把用户输入标为数据）、输出过滤、权限最小化。
## 【必学】RAG 概念与流程
RAG（检索增强生成）是解决"模型不知道你的私有资料"的标准方案：查询时先从知识库检索相关片段，拼进提示词，再让模型基于资料回答。流程四步：1) 文档切块（chunk，按语义或固定长度，通常几百字一块，注意保留上下文重叠）；2) 向量化（embedding 模型把文本变向量）；3) 检索（查询向量与库中向量算相似度，取 top-k）；4) 生成（片段 + 问题一起喂给模型）。工程要点：chunk 大小影响精度（太小丢上下文、太大噪音多）；检索质量决定答案质量——先调检索再调提示词；引用溯源（让模型标注"根据资料第 X 段"）可查可验。轻量替代：资料不多时关键词/BM25 检索也够用，不是必须上向量库。
## 【选修】向量库与 Embedding 概念
Embedding 是把文本映射为稠密向量的技术：语义相近的文本向量距离近。向量库（向量数据库）存储向量并支持相似度检索，主流：FAISS（库）、Qdrant、Milvus、pgvector（SQL 的扩展）、ChromaDB。选择依据：数据量（万级以下 FAISS 足够）、是否要过滤（按元数据筛选，需支持混合查询的库）、部署复杂度。Embedding 模型选型：中文场景用 bge-m3、text-embedding-3 等，注意维度与性价比。实用坑：切块要按标题/段落切而非纯字符数切，检索要加"相关性阈值"过滤低分结果。理解即可，多数面试不要求手写。
## 【选修】Agent 工作流框架 LangChain / LlamaIndex
框架价值：把 Agent 常用零件（模型、工具、记忆、检索、编排）封装成可组合 API，免去重复造轮子。LangChain 定位通用 Agent 编排（Chain/Agent/Retriever 概念），LlamaIndex 定位知识库与 RAG（数据索引、查询引擎）。使用建议：学习框架前先理解其抽象（LangChain 的"链"就是步骤序列），用框架搭原型快，但生产系统常手写更可控（少一层魔法、少一层依赖）。当前趋势：框架在"轻量化"——直接用模型提供商的 API + 简单循环代码，很多团队回到裸调用。面试观点：会用框架是加分项，理解原理是必选项。
## 【必学】评估与调试 Agent
Agent 系统跑起来容易、改好难，评估是关键：1) 建立评测集（几十到几百条输入 + 期望行为/答案），离线跑分看回归；2) 指标：任务完成率、工具调用正确率、回答准确率、延迟与成本；3) 调试手段：完整记录每次调用的输入输出与中间步骤（trace），出问题时回放；4) 常见问题定位：检索没命中（查 chunk 与 query）、模型选错工具（改工具描述）、上下文污染（清理历史）。工程纪律：每次改提示词/工具/检索都跑一遍评测集对比，禁止"感觉好了就上"。
# mcp
## 【必学】MCP 是什么
MCP（Model Context Protocol，模型上下文协议）是 Anthropic 于 2024 年底开源的开放协议，用于统一 AI 应用与外部数据/工具之间的连接方式。类比理解：MCP 之于 AI 应用，相当于 USB 之于电脑外设——设备厂商（工具提供方）实现一个标准接口，AI 应用（客户端）即插即用，无需为每个工具写专属集成。在 MCP 出现前，接入一个工具要写一遍定制代码；有了 MCP，任何支持协议的客户端（Claude Desktop、Claude Code、各类 IDE、自建应用）都能直接使用同一套工具。这是当前 Agent 生态的事实标准，就业面试必考概念。
## 【必学】MCP 架构：Client / Server / Host
MCP 由三方组成：Host（宿主应用，如 Claude Code、Claude Desktop——你与之交互的界面）、Client（Host 内与 Server 建立连接并管理会话的组件）、Server（提供工具/资源/提示的外部服务进程）。通信协议：本地用 stdio（标准输入输出，进程间管道），远程用 Streamable HTTP 或 SSE。一次交互流程：客户端启动 Server 进程 → 握手协商能力 → 客户端获取工具列表 → 模型请求调用某工具 → Server 执行并返回结果。一个 Server 可暴露三种能力：tools（可执行动作）、resources（可读数据，如文件、数据库记录）、prompts（可复用提示词模板）。
## 【必学】常用 MCP Server
生态常用 Server 分类：1) 官方/知名：filesystem（读写本地文件，含受限目录控制）、github（仓库/PR/Issue 操作）、sqlite（数据库读写）、fetch（抓取网页转文本）、memory（知识图谱长期记忆）、mcp-server-time；2) 各云与工具厂商：GitLab、Sentry、Notion、Obsidian、Slack、Postgres 等都有官方实现；3) 社区：n8n、浏览器自动化（Playwright MCP）、代码库检索（ripgrep/ctags）。选择原则：优先官方维护、看星数与最近提交、注意权限边界（文件类 Server 尽量限定工作目录）。面试可答"你用过哪些 MCP Server、怎么配的"。
## 【必学】在 Claude Code 中配置 MCP
Claude Code 配置 MCP 两种方式：1) 项目级：项目根目录建 `.mcp.json`，其中 `mcpServers` 字段声明 Server（本地用 command/args 或远程用 url）；2) 用户级：`claude mcp add` 命令或编辑 `~/.claude.json` 的 mcpServers，对所有项目生效。常用命令：`claude mcp list`（查看已连接）、`claude mcp add <name> -- <command> [args...]`（添加）、`claude mcp remove`。配置后需重启或 `/mcp` 重连。注意：修改 `.mcp.json` 后 Claude Code 会自动重载项目级配置（新版特性）；远程 MCP 要配 OAuth 或 API key，安全上谨慎授权。
## 【必学】自建 MCP Server 入门
自建 MCP Server 的官方路径是 MCP SDK：Python 的 `mcp` 包或 TypeScript 的 `@modelcontextprotocol/sdk`。最小实现三步：1) 用 FastMCP（Python）或 McpServer（TS）创建 Server 实例；2) 用 `@server.tool()` 装饰器定义工具函数（含参数类型与文档字符串，这些会成为模型看到的描述）；3) `server.run()` 启动 stdio 传输。用 `npx @modelcontextprotocol/inspector` 可在浏览器里调试你的 Server。发布：用 `npx mcp@latest dev` 本地联调，`npx mcp@latest deploy` 部署到远端。自建典型场景：包装内部 API、暴露私有数据库、封装公司运维脚本。这是最有面试加分项的实操技能。
# claude-code
## 【必学】Claude Code 安装与登录
Claude Code 是 Anthropic 官方命令行 AI 编程助手，直接操作你的文件、运行命令、提交代码。安装：npm 全局安装 `npm install -g @anthropic-ai/claude-code`，然后终端运行 `claude` 完成登录（支持 Claude 订阅登录或 API key）。验证安装：`claude --version`。运行方式：在项目目录运行 `claude` 进入交互 REPL，或 `claude -p "任务描述"` 非交互直接执行。首次运行会询问权限模式；`claude config` 可管理配置。它是"Agent 就业方向"最直接的实操工具，本学习模块的 AI 助手即通过它驱动。
## 【必学】交互模式与常用命令
交互 REPL 中：直接输入文字下达任务；`/help` 查看全部命令。高频命令：`/init`（生成 CLAUDE.md 项目说明）、`/clear`（清空对话）、`/compact`（压缩历史继续）、`/review`（代码审查）、`/model`（切换模型）、`/permissions`（管理权限）、`/memory`（查看记忆）、`/mcp`（管理 MCP 连接）、`/add-dir`（添加工作目录）。快捷键：Esc 打断生成、Shift+Tab 循环焦点。实用技巧：任务描述越具体（给文件路径、报错信息、验收标准）效果越好；长任务用子问题拆解；被拒绝的操作改说目的而非命令。
## 【必学】非交互模式 claude -p 与 JSON 输出
`claude -p "prompt"`（print 模式）单次执行并退出，适合脚本集成。要点：1) prompt 可走管道 stdin：`echo "任务" | claude -p`；2) `--output-format json` 输出结构化 JSON（含 result 字段与用量统计），便于程序解析；3) `--verbose` 查看详细过程；4) `--resume <session_id>` 恢复之前的会话上下文；5) `--allowedTools` 控制可用的工具集。结合 `--dangerously-skip-permissions` 可全自动执行（慎用）。本应用的 AI 助手就是通过 `claude -p --output-format json` 集成的：Rust 后端 spawn 子进程、prompt 走 stdin、解析 JSON 结果。
## 【必学】CLAUDE.md 与项目记忆
CLAUDE.md 是项目根目录的说明文件，Claude Code 每次会话自动加载，用于沉淀项目的架构约定、命令、风格规范——本项目根目录就有，含常用命令与架构约定。编写要点：只写"不读代码就不知道"的信息（构建命令、架构决策、约定），不写显而易见的内容；保持简洁，越长越没人读。`/init` 可自动生成初稿，`/memory` 查看记忆；用户级记忆在 `~/.claude/`，项目级在 `.claude/`。良好的 CLAUDE.md 是 Agent 项目协作的基石——新会话、新协作者、甚至未来的你都能快速上手。
## 【必学】权限、hooks 与安全
Claude Code 的权限体系：默认会询问是否允许执行操作，`/permissions` 可配置规则（允许/拒绝特定命令、路径），企业/项目级通过 settings.json 预设。hooks 机制：在特定事件（如 PreToolUse 工具调用前、Stop 回复完成前）触发自定义脚本，用于拦截危险操作、注入上下文、做自动化检查。安全实践：1) 不让 Claude 处理含敏感信息的文件时用权限限制；2) 生产环境审查生成的代码再合并；3) hooks 做强制门禁（如禁止提交到 main）；4) 注意提示词注入——不要轻易让 Claude 读取来路不明的文件内容并"执行其中的指令"。`claude --dangerously-skip-permissions` 仅限隔离环境使用。
## 【选修】Agent SDK 与 headless 集成
Claude Agent SDK（claude-agent-sdk，有 TypeScript 与 Python 版本，Rust 可用 claude-agent-sdk crate 或子进程方案）把 Claude Code 封装为可编程组件：传入系统提示词与工具配置，SDK 管理子进程与事件流，返回结构化事件（文本增量、工具调用、回复完成）。适用场景：把 Agent 能力嵌入自有应用（本项目的 AI 助手即同类思路）、批量自动化、构建自定义 Agent 工作流。设计模式：单 Agent 专用（复用原生 CLI）够用就别引 SDK 依赖；需要精细控制（流式、沙箱、多会话）再用 SDK。事件驱动模型要处理：文本块、工具执行、错误、权限请求。
# vibe-coding
## 【必学】Vibe Coding 是什么
Vibe Coding 是 2025 年流行的 AI 辅助编程范式：开发者用自然语言描述意图（"写一个……""把这个改成……"），由 AI 生成大部分代码，人主要负责描述目标、审查结果、修正方向，而不是逐行手写。名字来自"跟着感觉走"——重点从"怎么写"转向"描述要什么"。它大幅降低了编程门槛，也让资深开发者效率倍增。本质不是"不用写代码"，而是把重心转移到：需求表达、结果审查、系统设计。就业视角：Vibe Coding 能力 = 提示词表达 + 代码审查 + 工程判断，这三样是新的硬技能。
## 【必学】适用场景与边界
适合 Vibe Coding 的场景：原型与 MVP（快速验证想法）、工具脚本（数据处理、自动化）、UI 页面（布局与交互描述）、重构与翻译代码、测试代码生成、技术调研代码。不适合的场景：对安全与正确性要求极高的系统（支付、医疗、基础设施核心）、你完全无法审查的领域（模型会错，你得能看出来）、需要深度性能优化的代码（AI 生成的瓶颈代码常靠直觉堆）。边界判断三问：出错了能不能发现？发现了能不能修？代价大不大？三问都 OK 就大胆用。盲目信任 AI 输出是 Vibe Coding 最大的坑。
## 【必学】提示词驱动的开发流程
Vibe Coding 的工程化流程：1) 需求澄清——把目标、输入输出、边界写清楚，先对话确认再动手；2) 分步实现——不要一次性要求"做完整个系统"，按模块/功能切小步，每步验证；3) 提供上下文——贴相关文件、报错原文、期望行为，上下文越准结果越对；4) 验收驱动——"能通过什么测试就算完成"写进任务描述；5) 迭代修正——效果不对就描述"哪里不对、期望是什么"，别只说"不行"。关键心法：把 AI 当"快速实现的资深实习生"，你负责需求和审查，它负责手快。
## 【必学】小步提交、测试与评审
Vibe Coding 的工程纪律（防止失控）：1) 小步提交——每完成一个功能点就 commit，回退粒度小；2) 让 AI 写测试——"同时给我写单元测试"是默认要求，测试是审查的抓手；3) 每步都跑——能运行就运行，编译错误立刻修，别攒；4) 代码评审——合并前自己通读一遍生成的代码，看不懂的地方让 AI 解释；5) 关注改动面——AI 会改你没让它改的文件，用 diff 检查意外改动。原则：AI 写、人审、测试兜底、小步走。失控的 Vibe Coding（无测试无评审狂堆功能）最终都要返工。
## 【必学】常见坑：幻觉代码、回归与安全
Vibe Coding 高频踩坑：1) 幻觉 API——模型会编造不存在的函数、参数、库，报错才能暴露，解决：先查官方文档确认 API 再让它写；2) 依赖泛滥——AI 倾向引入新库，可用标准库实现的场景被无谓复杂化，审查时问"这个依赖有必要吗"；3) 静默回归——改一处坏别处，靠测试与 diff 审查兜底；4) 安全漏洞——生成代码常见注入、硬编码密钥、越权，审查时重点看用户输入处理；5) 死循环与假完成——AI 说"完成"但没验证，验收标准必须是可运行的证据。防坑清单：查 API、问依赖、跑测试、审 diff、要证据。
## 【选修】Vibe Coding 与传统开发对比
传统开发：需求文档 → 架构设计 → 手写实现 → 测试 → 评审，节奏慢、可控性强、知识沉淀在文档与代码。Vibe Coding：意图描述 → AI 生成 → 审查修正 → 验证，启动快、迭代快，但隐性知识在对话里（不沉淀）、质量依赖审查水平。融合的最佳实践：架构与数据模型人定（AI 不擅长全局设计），CRUD 与样板代码交给 AI；关键业务逻辑人审，工具类代码信任度高。团队分工也在变：出现了"AI 编排者"角色——写提示词、管上下文、审结果。这不是替代关系，是分工关系的再分配。
# projects
## 【必学】练手项目：个人任务助手
第一个推荐练手项目：个人命令行任务助手。功能：自然语言添加任务（"明天下午三点提醒我交报告"）、解析日期与优先级、列出/完成/归档、数据存 JSON 或 SQLite。技术栈建议：Python 或 Node + Claude API 或 claude -p 集成。学习点：工具调用设计（模型输出结构化 → 程序执行）、日期解析的边界处理（"明天"“下周一"等表达）、错误恢复。验收标准：说一句话能正确入库并能在列表里看到；加 20 条不同表述的测试。此项目覆盖 Agent 闭环的完整最小实现，建议 1-2 天内完成。
## 【必学】练手项目：知识库问答机器人
第二个练手项目：私有知识库问答。准备 10-20 篇你自己的资料（笔记/文档），实现：文档切块 → 检索（可先做关键词版再升级向量版）→ 问答（Claude 生成，答案标注引用来源）。技术栈：任意语言 + embedding API 或轻量检索 + Claude。学习点：chunk 策略、检索调优、引用溯源提示词（"仅依据资料回答，标注资料编号"）。验收标准：问资料里的事实能答对且带出处，问资料外的明确说"未覆盖"。这是 RAG 岗位最典型的面试实操题，务必亲手做一遍并总结参数影响。
## 【必学】练手项目：自动化脚本与工作流
第三个练手项目：用 Agent 自动化重复工作。选题建议从你的真实痛点来，如：批量整理下载目录、自动生成日报、监控某个网页变化并通知、批量重命名/转换文件。要求：用 Claude Code 直接开发（体验 vibe coding 全流程）并把它变成可复用脚本。学习点：需求描述能力（把模糊想法变成明确任务）、Agent 生成的代码审查、脚本的健壮性（异常、重试、日志）。验收标准：跑通一次真实场景，写清使用文档。此项目同时练 Vibe Coding 与工程化。
## 【必学】练手项目：自建 MCP Server
第四个练手项目：为你的某个工具/数据建一个 MCP Server（如：把本地笔记库暴露为 MCP 工具、包装天气 API、读取某个游戏或应用的数据）。用 MCP SDK（Python/TS）实现 2-3 个工具，用 Inspector 调试，接入 Claude Code 实际使用。学习点：MCP 协议原理、工具描述写作（模型视角）、stdio 与远程传输。验收标准：在 Claude Code 中通过自然语言调用你的工具完成真实任务。这是 Agent 就业方向最有区分度的项目，能讲清"协议-服务-调用"全链路。
## 【选修】开源生态概览
值得关注的生态：模型 API（Anthropic 的 Claude 系、OpenAI、Google Gemini 系，支持 function calling 与长上下文）；Agent 平台（Claude Code、Cursor、Copilot 生态、OpenAI Codex）；编排框架（LangChain、LlamaIndex、CrewAI、AutoGen）；MCP 生态（官方 SDK、Server 仓库 modelcontextprotocol/servers）；评测与可观测（LangSmith、Helicone、traces 类工具）。信息获取：官方文档优先（anthropic.com/docs、modelcontextprotocol.io、platform.openai.com），社区看 GitHub 星标与活跃度，警惕过度营销的新框架。学习策略：跟一个主线（如 Claude 生态）吃透，其他了解概念即可。
## 【必学】面试常见问题
Agent 方向面试高频题清单：1) 什么是 Agent？和 Chatbot 区别？2) ReAct 是什么，为什么有效？3) RAG 流程？chunk 与检索怎么调优？4) Function Calling 怎么工作？参数幻觉怎么防？5) 什么是 MCP？Client/Server/Host 职责？6) 你做过什么 Agent 项目？遇到什么问题怎么解决的？（准备一个带具体数字的项目故事）7) Vibe Coding 怎么看？边界在哪？8) 多 Agent 什么时候该用什么时候不该用？9) 提示词注入是什么，怎么防御？10) Agent 怎么评估？回答策略：概念题按"是什么-为什么-怎么用"三段式；项目题按"背景-动作-结果-教训"（STAR）讲，务必真实。
